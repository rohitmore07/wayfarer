# Wayfarer AI

A conversational travel-planning agent. You describe the trip you want in plain language — "7 days in Japan in March, ₹1.5L per person, culture and food, anime, photography" — and six specialist agents research the destination, compare flights and stays, route a day-by-day itinerary, price it, and hand you an editable workspace where you keep talking to refine the plan.

> **Demo data notice.** Flight fares, hotel rates and availability in this build are generated by clearly labelled sandbox adapters. Nothing here is a bookable quote and Wayfarer never claims a booking is confirmed. Weather is live (Open-Meteo, no key required). Every figure in the product carries a provenance label: **Live data**, **Estimated**, **AI recommendation** or **Demo data**.

## Environment variables

Everything works with **zero keys configured**. Each integration is optional and switches on when its key is present.

Copy `.env.example` to `.env.local` and fill in whatever you have:

| Variable | Effect when set | Fallback when absent |
| --- | --- | --- |
| `OPENAI_API_KEY` (+ `OPENAI_MODEL`) | LLM-written brief parsing, follow-up questions and plan narration | Deterministic parser + template narration in `lib/agent/parse.ts` |
| `GEMINI_API_KEY` (+ `GEMINI_MODEL`) | Same, via Google Gemini | as above |
| `AMADEUS_CLIENT_ID` / `AMADEUS_CLIENT_SECRET` | Live flight offers from the Amadeus Self-Service API | Sandbox fare engine, labelled **Demo data** |
| `GOOGLE_MAPS_API_KEY` | Live map tiles instead of the built-in vector map | Stylised vector map (`components/trip/TripMap.tsx`) |
| `SESSION_SECRET` | Deterministic session token signing | Random per-install tokens in `data/db.json` |

Weather uses Open-Meteo and needs no key; when a date is beyond the 16-day forecast horizon the app falls back to ten-year climate normals and labels them **Estimated**.

### The agent

`lib/agent/orchestrator.ts` is the planner. It runs six steps in sequence and streams each one to the browser as newline-delimited JSON (`POST /api/agent/plan`):

1. **Brief parsing** — extracts destination(s), month, duration, travellers, budget, interests and style from plain text; asks a follow-up question when something material is missing.
2. **Destination research** — seasonality, safety notes, visa/entry guidance and what is actually worth the time (`lib/agent/destination.ts`).
3. **Flight search** — outbound + return comparison, tagged cheapest / fastest / recommended, with baggage, layover and CO₂ detail.
4. **Hotel shortlisting** — scored on price fit (30), guest score (25), proximity to your actual itinerary anchors (28), tier match (12) and value (10).
5. **Itinerary** — day-by-day morning/afternoon/evening routing that keeps each day geographically tight, respects opening hours and meal times, and prefers indoor alternatives when rain is likely.
6. **Budget** — flights + stay + food + transport + activities + shopping + visa/insurance, per person and per day, with warnings and savings tips; if the estimate overshoots the target by more than 8% the agent auto-optimises (cheapest sensible flight + cheapest high-rated stay) and says so.

**Refinement** (`refinePlan`) applies natural-language edits — *make it cheaper, swap the hotel, add a day in Kyoto, no early mornings, more adventure, alternative flights, reduce the budget to ₹1 lakh* — and changes only the sections the edit touches. Every change is reported back as a numbered "what changed" list.

`lib/agent/llm.ts` wraps an optional LLM (OpenAI or Gemini) for phrasing and flexible parsing; when no key is present the deterministic path produces the same structured output, so the product is fully functional offline.

### Data model & persistence

- `lib/db/store.ts` — a small JSON store (`data/db.json`) with atomic writes, scrypt password hashing, session tokens, user-scoped trips, conversations and documents. Swap this file for Prisma/Postgres behind the same functions; nothing else in the app talks to storage directly.
- `lib/types.ts` — the shared contract: `TravelBrief`, `Flight`, `Hotel`, `Poi`, `ItineraryDay`, `BudgetPlan`, `Trip`, `PlanPayload`, `ChatMessage`, `AgentStep`, plus the `Provenance` union used by every badge.
- `lib/trips.ts` — converts an agent `PlanPayload` into a persisted `Trip` and re-prices it when anything is edited.

Every API route validates its input with zod, is scoped to the signed-in user, and returns structured errors.

### Domain modules

- `lib/providers/flights.ts` — fare engine (distance × cabin × competition × season) and the Amadeus adapter hook.
- `lib/providers/hotels.ts` — hotel inventory, amenity/property filters and the scoring used for recommendations.
- `lib/providers/weather.ts` — live forecast via Open-Meteo plus climate normals for far-future dates.
- `lib/data/` — 16 destinations, ~100 real points of interest with descriptions and photography, airlines, airports and hotel inventory.
- `lib/agent/budget.ts` — the cost model (multi-city stays, per-person/night room maths, visa table).
- `lib/extras.ts` — packing list and safety briefing generators (pure, client-safe).

## Design system

Linear/Notion restraint with an Airbnb warmth: ivory `#FAF8F4` canvas, sand `#F3EFE7` panels, ink `#17150F` type, clay `#C05B34` for action, pine `#1F4A43` for confirmation, gold `#C99A4B` for attention. Instrument Serif for display, Inter for UI (both self-hosted in `public/fonts`). Tokens live in `tailwind.config.ts` and `app/globals.css`; the primitives (`Button`, `Badge`, `ProvenanceBadge`, `EmptyState`, `Skeleton`, `Rating`, `Stat`, `Avatar`, `FadeIn`) live in `components/ui`.

Layout is responsive down to 390 px: the desktop sidebar becomes a sticky top bar plus bottom tab bar, and every grid is `min-w-0`-safe so long flight cards never push the page sideways.

## Honest limitations

- **No bookings.** No GDS or bedbank is connected; fares and rates are modelled, not quoted. Provider gaps are labelled "Demo data" in the UI.
- **Hotel photography** pairs destination-accurate interiors with demo property records.
- **Maps** are a stylised vector projection unless `GOOGLE_MAPS_API_KEY` is set.
- **Auth** is cookie-session based for a single-server demo; production would move to an identity provider with CSRF protection and rate limiting on `/api/auth/*`.
- **Storage** is a JSON file. It is atomic and user-scoped, but a real deployment should use Postgres (`lib/db/store.ts` is the only module to swap).
- The agent is intentionally deterministic without a key: it prioritises reproducibility over free-form creativity. Add an LLM key to get more conversational phrasing and looser brief parsing.
